# 把多处结果当作待处理清单

> 来源：Neovim Quickfix/位置列表 + LazyVim/Trouble 入口。

## 什么时候用

编译报错、搜索结果分散在多个文件，要按顺序逐项查看时使用。

## 怎么用

| 模式 / 场景 | 键位或命令                  | 会发生什么                                     |
| ----------- | --------------------------- | ---------------------------------------------- |
| 普通        | `<leader>xq`                | 打开或关闭原生 Quickfix 列表。                 |
| 普通        | `<leader>xl`                | 打开或关闭当前窗口的位置列表。                 |
| 普通        | `<leader>xQ` / `<leader>xL` | 用 Trouble 查看 Quickfix / 位置列表。          |
| 普通        | `]q` / `[q`                 | Trouble 打开时跳其条目，否则跳 Quickfix 条目。 |
| 命令        | `:cnext` / `:cprev`         | 明确跳 Quickfix 的下一 / 上一项。              |
| 列表窗口    | `Enter`                     | 跳到这一项的文件与行号。                       |

## 跟着做一次

手动建立一个可重复查看的搜索清单：执行 `:vimgrep /TODO/j **/*.lua`，再用 `<leader>xq` 打开结果，Enter 跳转。回到代码后用 `:cnext` 继续检查下一条。

## 在你的配置里

Quickfix 是一份全局结果清单，位置列表归属于窗口。它们与 LSP 的持续诊断不是一回事，也不会自动因为修复代码就删除旧条目；必要时重新执行生成列表的搜索或检查。

## 继续查

原生帮助：`:help quickfix`、`:help location-list`。
