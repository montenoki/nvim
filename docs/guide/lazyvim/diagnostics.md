# 阅读错误、警告和问题列表

> 来源：Neovim 诊断 + LazyVim；Trouble 负责组织列表。

## 什么时候用

文件里有多个错误，想逐个修复，或者把整个项目的问题汇总起来时使用。

## 怎么用

| 模式 / 场景  | 键位或命令   | 会发生什么                    |
| ------------ | ------------ | ----------------------------- |
| 普通         | `<leader>cd` | 查看当前行诊断详情。          |
| 普通         | `]d` / `[d`  | 下一个 / 上一个诊断。         |
| 普通         | `]e` / `[e`  | 只跳错误。                    |
| 普通         | `]w` / `[w`  | 只跳警告。                    |
| 普通         | `<leader>xx` | 切换诊断列表（Trouble）。     |
| 普通         | `<leader>xX` | 只看当前文件诊断（Trouble）。 |
| 普通         | `<leader>cS` | 查看 LSP 引用、定义等列表。   |
| Trouble 列表 | `Enter`      | 跳到选中项。                  |

## 跟着做一次

先按 `<leader>xX` 看当前文件的问题列表，选中一条 Enter 跳过去，再用 `<leader>cd` 读完整消息。改完之后等待服务器重新检查，列表会跟着变化。

## 在你的配置里

诊断可能来自 LSP，也可能来自 lint 工具。列表为空不证明整个项目绝无错误：有些服务器只检查已打开文件，独立测试仍要运行。`<leader>ud` 只是诊断显示开关，不是修复错误。
