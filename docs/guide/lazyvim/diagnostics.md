# 阅读错误、警告和问题列表

> 来源：Neovim 诊断 + LazyVim；Trouble 负责组织列表。

## 什么时候用

文件里有多个错误，想逐个修复，或者把整个项目的问题汇总起来时使用。

## 怎么用

| 模式 / 场景  | 键位或命令   | 会发生什么                    |
| ------------ | ------------ | ----------------------------- |
| 普通         | `<leader>xd` | 查看当前行诊断详情。          |
| 普通         | `<leader>xx` | 切换全部已收集诊断列表并聚焦。     |
| 普通         | `<leader>k` | 查看 LSP 引用、定义等列表。   |
| Trouble 列表 | `Enter`      | 跳到选中项。                  |

## 跟着做一次

先按 `<leader>xx` 查看所有已收集诊断，选中一条 Enter 跳过去，再用 `<leader>xd` 读完整消息。改完之后等待服务器重新检查，列表会跟着变化。

## 在你的配置里

`<leader>xt` 查看 cwd 内全部受支持 TODO 标记，扫描遵循忽略规则，以保存到磁盘的内容为准。

诊断可能来自 LSP，也可能来自 lint 工具。列表为空不证明整个项目绝无错误：有些服务器只检查已打开文件，独立测试仍要运行。`<leader>ud` 只是诊断显示开关，不是修复错误。
