# 整理代码格式

> 来源：LazyVim + conform.nvim；具体工作交给外部格式化工具。

## 什么时候用

缩进和换行不统一，或者改完代码想遵守项目格式约定时使用。

## 怎么用

| 模式 / 场景 | 键位或命令     | 会发生什么                                         |
| ----------- | -------------- | -------------------------------------------------- |
| 普通        | `<leader>cf`   | 手动格式化当前文件。                               |
| 可视        | `<leader>cf`   | 请求格式化所选范围；效果取决于格式化器的范围支持。 |
| 普通        | `<leader>uf`   | 切换全局保存时自动格式化，并记住选择。             |
| 命令        | `:ConformInfo` | 查看本文件可用的格式化器和日志。                   |
| 普通        | `<leader>cF`   | 格式化嵌入语言；需要对应解析与格式化支持。         |

## 跟着做一次

打开一份缩进混乱的 YAML，先按 `<leader>cf` 看结果。如果只想手动整理，按 `<leader>uf` 关掉自动格式化，之后保存不会再按这个全局开关自动排版。

## 在你的配置里

Markdown、JSON、JSONC、YAML 显式使用 Prettier；Nix、Python 等还继承语言 Extra 的配置。工具必须在 Neovim 的环境中可用，Nix 工具托管环境不靠 Mason 临时下载。格式化不等于修复程序逻辑或替代 lint。
